Telegram 媒体转存与任务管理

tg_transfer_bot

基于 TDLib 的长期运行型转存服务。通过私聊按钮完成源消息选择、目标选择、进度跟踪、结果跳转、任务恢复和权限管理。

单条与相册转存 下载缓存与断点恢复 Owner 与动态授权

主要能力

交互入口以按钮为主，命令保留为快速入口和故障兜底。

TRANSFER

转存与结果跳转

支持链接、回复媒体、直接发送媒体和相册；完成后保存目标消息地址。

PROGRESS

单消息进度卡

选项、排队、下载、上传和结果尽量更新在同一条消息中，减少刷屏。

CACHE

本地文件缓存

按 TDLib client 隔离缓存；本地文件仍存在时直接复用并跳过下载。

RECOVERY

任务恢复

任务、子项、结果和输入草稿持久化，重启后继续处理未完成任务。

ACCESS

交互式授权

Owner 可选择 Telegram 用户、输入 ID、查看管理员名称并撤销动态授权。

CONTROL

任务控制

支持状态筛选、详情、暂停、恢复和安全停止。

快速启动

优先使用 GitHub Release 中已打包的运行包；从源码构建时才需要单独准备 TDLib。

1. 使用 Release 包

从 GitHub Releases 下载与系统一致的 x86_64 包。当前正式包覆盖 Alpine 3.23、Debian 13、Ubuntu 24.04 和 Windows，并附带 SHA-256 校验文件。

Linux · Alpine 3.23
tar -xzf transfer_bot-linux-x86_64-alpine3.23.tar.gz
cd transfer_bot-linux-x86_64-alpine3.23
cp config.example.json config.json
# 填写 config.json 后启动
./run.sh -c config.json
PowerShell · Windows
Expand-Archive .\transfer_bot-windows-x86_64-msvc.zip -DestinationPath .\release
Set-Location .\release\transfer_bot-windows-x86_64-msvc
Copy-Item .\config.example.json .\config.json
# 填写 config.json 后启动
.\run.ps1 -c .\config.json

2. 从源码启动

以下命令适用于 Windows PowerShell。构建前需要准备可用的 TDLib，并让目录包含 include、lib 和 bin/tdjson.dll。

2.1 设置 TDLib 路径

PowerShell
$env:LOCAL_TDLIB_PATH = "F:/tdlib/td/tdlib"

2.2 准备配置

以仓库中的 config.example.json 为模板创建本地 config.json。不要提交真实 token、API Hash 或数据库密钥。

2.3 Debug 日志启动

PowerShell · config.json
$env:LOCAL_TDLIB_PATH = "F:/tdlib/td/tdlib"
$env:RUST_LOG = "transfer_bot=debug,info,sea_orm=warn,sqlx=warn,tokio=warn"
cargo run -p transfer_bot -- -c config.json
登录成功判断 日志出现 tdlib authorization ready 表示对应 client 已完成授权；出现 starting transfer background services 表示后台恢复与缓存服务已启动。

Docker 部署

镜像基于 Alpine 3.23，包含 transfer_bot、TDLib 及运行时依赖。GitHub Actions 会推送最新 Release 对应的版本标签和 latest 标签。

1. 拉取镜像

Docker
docker pull ghcr.io/smagicalk/tg_transfer_bot:latest

2. 挂载配置和数据目录

以下示例适用于 Windows Docker Desktop。配置样例中的 tg/ 为相对路径，必须映射到 /app/tg，否则容器重建后 TDLib 登录态、文件缓存和 SQLite 数据库会丢失。

PowerShell · Debug 日志
docker run -d --name tg_transfer_bot `
  --restart unless-stopped `
  --mount "type=bind,source=F:/tg-transfer-bot/config.json,target=/config/config.json,readonly" `
  --mount "type=bind,source=F:/tg-transfer-bot/tg,target=/app/tg" `
  -e CONFIG_PATH=/config/config.json `
  -e RUST_LOG=debug `
  ghcr.io/smagicalk/tg_transfer_bot:latest

CONFIG_PATH 默认是 /app/config.json，配置文件映射到其他位置时修改该环境变量即可。若 GHCR 包仍为私有包，先执行 docker login ghcr.io。

镜像发布流程 手动运行 Publish Alpine Container Image 时，工作流直接下载最新 Release 的 Alpine 包并生成镜像。仅当附件意外缺失时，才从同一 Release tag 的源码构建运行包兜底；镜像 tag 始终与最新 Release tag 保持一致。

配置文件

启动级配置保存在 config.json；目标、别名、运行参数和动态授权保存在业务数据库中。

字段用途要求
config_version配置结构版本当前为 2
owner_user_id唯一 Owner 用户 ID必须大于 0
admin_user_ids静态管理员名单可为空数组
tdlib_defaults.api_idTelegram API ID使用自己的凭据

storage.database_url业务数据库SQLite 或 PostgreSQL
clients.user按需执行器目录由 Owner 在 Bot 内二维码登录

{

  "owner_user_id": 123456789,
  "admin_user_ids": [],
  "tdlib_defaults": {
    "api_id": 0,
    "api_hash": "replace_me",
    "log_verbosity_level": 1
  },
  "storage": {
    "database_url": "sqlite://tg/app/transfer.sqlite?mode=rwc"
  },
  "clients": {
    "user": {
      "tdlib": {
        "database_directory": "tg/user/db",
        "files_directory": "tg/user/files",
        "database_encryption_key": "replace_me"
      }
    },

      "token": "replace_me",
      "tdlib": {
        "database_directory": "tg/bot/db",

权限边界

所有操作以发送者的 Telegram 用户 ID 校验，不使用群组 ID 代替用户身份。

  • 只处理已授权用户与 Bot 的私聊交互。
  • owner_user_id 始终拥有完整权限。
  • admin_user_ids 和数据库动态授权用户可执行日常转存与任务管理。
  • 只有 Owner 可以打开授权面板、添加或删除动态管理员。
  • 群聊和频道中的命令不会进入管理流程，避免使用 chat ID 误判权限。

授权操作

打开授权管理Owner 点击菜单中的授权管理
选择添加使用 Telegram 用户选择器
确认用户显示名称、username 和 user_id
立即生效写入数据库和运行时授权集合
列表管理按名称查看并撤销动态授权

运行机制

业务数据库与 TDLib 数据目录分离。任务状态负责恢复，文件缓存负责减少重复下载，运行时上下文负责实时进度。

交互层 命令、callback、ForceReply、聊天和用户选择器
→
任务层 任务创建、去重、恢复、下载、上传和结果记录
→
持久化层 transfer_job、transfer_item、file_cache、授权与配置

文件处理

  1. 按消息提取稳定的 remote.unique_id 作为 file_key。
  2. 按 owner_client_role + file_key 查询缓存，Bot 与 User 缓存严格隔离。
  3. 缓存状态为 ready 且本地文件存在时，直接使用 InputFile::Local。
  4. 缓存失效时由 TDLib 下载，并通过 single-flight 合并并发下载。
  5. 引用归零后进入延迟删除队列，由 GC 清理本地文件。
